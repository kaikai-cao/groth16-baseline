Bottleneck 分析
前面的 Groth16 Prover 系统级 profiling 表明，随着约束规模扩大，Prover 的主要计算开销集中在 QAP 后的 A、B、C 计算阶段。Day 11 进一步对底层 MSM 与 FFT 进行了独立 microbenchmark。结果显示，在当前 BN254 与 arkworks 0.6.0 实现下，MSM 是更值得关注的局部热点：1～100 万约束范围内，MSM 总时间约占 Prover 的约 90% 以上（单线程），即使使用 20 线程仍保持在约 71%～83%。其中 B-G2 MSM 始终是五个 MSM 中耗时最高的单项。相比之下，FFT 在 \(2^{10}\)～\(2^{16}\) 规模下绝对耗时较低，并且仅在较大规模时表现出明显并行收益：20 线程相对于 1 线程的加速比从小规模的低于 1 提升到 65536 时约 4.2～4.3 倍。这说明局部算子的性能高度依赖规模、并行策略和具体实现，不能仅依据理论复杂度判断实际成本。同时，局部算子获得 50% 加速并不意味着 Prover 总体获得 50% 加速，整体收益受其他未优化阶段和串行部分限制。因此，当前 baseline 的后续优化应优先围绕 MSM，尤其是 B-G2 MSM 展开。
